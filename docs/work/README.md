# Documente de lucru

`work/` face legătura dintre discuția de produs, planificarea tehnică, implementare și reconcilierea finală.

- [`active/`](active/) — funcționalități și inițiative în desfășurare;
- [`archive/`](archive/) — documente închise după ce adevărul curent a fost transferat în sursele canonice.

Un document de lucru poate include:

- intenția și comportamentul dorit;
- constrângerile și criteriile de acceptare;
- checkpoint-ul Git de început;
- deciziile luate în timpul implementării;
- rezultatul și checkpoint-ul Git final;
- reconcilierea cu documentația canonică.

Git este evidența implicită a implementării. Raportul de încheiere al agentului de implementare rămâne în task și nu se copiază automat într-un document. Notează separat numai deciziile sau motivele importante care nu pot fi deduse din cod și commituri.

Nu crea un document pentru fiecare idee sau schimbare minoră. Folosește un singur document pentru un rezultat coerent și numai când complexitatea sau continuitatea lui justifică documentul.
